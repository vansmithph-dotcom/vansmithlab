# Content Model and Publication Structure

## Supported public formats

| Format | Primary purpose | Authorship |
| --- | --- | --- |
| Encyclopedia entry | Neutral, updateable definition of an object | VANSMITHLAB |
| Glossary | Fast explanation of a term or concept | VANSMITHLAB |
| Research | Long-form evidence-led investigation across objects | VANSMITHLAB |
| Case study | Context, process, result and significance of a specific work | VANSMITHLAB |
| Visual analysis | Explain visual language, materials, composition or image logic | VANSMITHLAB |
| Timeline | Dated, cited events and periods | VANSMITHLAB |
| Collection | Curated, explicit grouping with selection rationale | VANSMITHLAB |
| Gallery / video | Media-led explanation tied to sources and transcript/captions | VANSMITHLAB |
| Analysis / essay | Clearly attributed argument or interpretation | Signed or attributed |

## Publication anatomy

Every page must contain:

1. Title and one-sentence answer/definition.
2. Type, verification state, confidence, last reviewed date and language switcher.
3. Core explanation structured for the format.
4. Related objects, chronology and discovery links.
5. Source/citation access and version/correction history.
6. Rights, credit and AI disclosure for relevant media.

### Person profile minimum

People pages use a two-layer visual contract: the list card visualizes the person's method or field of work, while the article contains a separate portrait. The article must also contain a sourced set of ten notable works, projects, series, publications or comparable contributions, or explicitly state why fewer than ten can be verified. These are factual items and must be backed by claims and sources; they are not decorative recommendations.

## Article and analysis distinction

An institutional article explains what evidence supports. A signed analysis may argue why it matters. The analysis template must label interpretive sections, name the author and link its claims to neutral knowledge objects.

## Publication state machine

`idea → briefed → researching → evidence_ready → drafted → edited → validated → published → monitoring`

Branches: `auto_revise`, `blocked`, `needs_user_input`, `retracted`, `archived`.

No page moves to `published` because prose looks complete; it moves only through an evidence, rights, localization and technical release gate.
